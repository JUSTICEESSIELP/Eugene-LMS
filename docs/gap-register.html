Correctness & security

Each one verified in the code or by signing in as the affected role — not inferred.

G-01

Exam submission skips every check that GET enforces

~1 hour
Evidence
POST /api/exams/:id/submit calls gradeSubmission(), which looks up the exam by id and grades it. There is no check on the student's class, on isActive, or on dueDate — while GET /api/exams/:id correctly 403s a student from another class. code-read
Impact
A student can submit against any exam id: another class's paper, an unpublished draft, or one long past due, and it records a score. They cannot read the questions (the GET is guarded), so this is data pollution rather than cheating — but the inconsistency makes it a bug, not a decision.
Fix
Move the class / active / due-date guard into gradeSubmission so both paths share it.
G-02

The router never checks a role

~30 min
Evidence
Signed in as a parent — the lowest-privilege role — and opened /admissions, /classes, /subjects, /users/admins and /settings/academic-years by typing the URL. Every admin screen rendered in full, buttons and forms included. tested live
Impact
No data leaks — every table came back empty because the API returns 403, which is the boundary that matters. But the UI offers controls that cannot work, to people who should not see them.
Fix
A role guard on the private route branch, the same shape as the sidebar filter that already exists.
G-03

No password policy on the server

~20 min
Evidence
The React form requires 6–8 characters, but POST /api/users/register validates only that password is present. Anything that talks to the API directly bypasses the rule. code-read
Impact
Single-character passwords are accepted on a real account. Client-side validation is a convenience, never a control.
Fix
Enforce a minimum length server-side in register and update, returning 400.
G-04

The one public write endpoint is unthrottled

~30 min
Evidence
No rate limiting anywhere in the Worker. POST /api/applications needs no session. code-read
Impact
Anyone can flood the admissions table. The duplicate-pending guard only stops the same email applying twice to the same programme — varying either walks straight past it. Once acceptance emails go out, this becomes a way to make Veya send mail.
Fix
A Cloudflare Rate Limit binding applied before the insert — the same pattern the Workplace Files project already uses.

Dead ends

Flows that start, look like they worked, and then stop. These are what make the app feel broken even where nothing errors.

G-05

Accepting an application does nothing

in progress
Evidence
Accepted a real application on production and re-queried: status changed to accepted, an audit line was written, and the user count stayed at 2. No account, no email. tested live
Impact
The applicant cannot log in and never learns the outcome. An admin must retype every accepted person into the student form by hand.
G-06

Applying produces no signal at all

in progress
Evidence
The form writes a row and shows a confirmation screen. No email is sent, and there is no way for an applicant to check status later.
Impact
From the applicant's side the submission vanishes. This is the single most common “is it broken?” moment in the product.
G-07

Forgetting a password locks you out permanently

~3 hours
Evidence
No reset, recovery or forgot-password route exists in either the SPA or the API. code-read
Impact
The only recovery is an admin editing the record and telling the person their new password out of band. For a student body of any size this becomes the admin's whole job.
Fix
Now unblocked — once Resend is wired, a single-use expiring reset token is straightforward.
G-08

The parent role is a shell

~1 day
Evidence
Created a parent and signed in. Landed on the student dashboard showing 0%, 0, None; the menu offered Dashboard, Timetable and Attendance; exams, classes and subjects all returned 403. tested live
Impact
An admin can create an account that leads nowhere. There is no parent→child link on the user record, so there is nothing to show even if a page existed.
Fix
Hide the role from the creation dropdown today (minutes); build it properly later.
G-09

Teachers cannot see results

~4 hours
Evidence
Submissions are graded and stored, and the API can return any student's result, but no screen lists them. The teacher dashboard shows a “pending grading” count that leads nowhere.
Impact
The assessment loop never closes. Work is marked and then invisible.
G-10

Exam duration is decorative

~2 hours
Evidence
{exam.duration} Minutes is rendered on the exam page. Nothing starts a timer, and the submit endpoint does not check elapsed time. code-read
Impact
A timed assessment that is not timed. Displaying the limit implies enforcement that does not exist.

Missing & incomplete

Advertised in the interface, absent from the codebase — plus the data-integrity work that was never done.

G-11

Attendance does not exist, but is reported anyway

~2 days
Evidence
No attendance table, model or endpoint. The dashboards return the string literals "94.5%" and "98%", both marked as placeholders in the source. code-read
Impact
The app shows a confident, invented statistic to admins and students. This is the worst of the missing features, because it does not look missing.
G-12

Deleting a record leaves dangling references everywhere

~4 hours
Evidence
Only exam deletion cascades (to submissions). Deleting a subject leaves its id inside classes.subjects, users.teacherSubject and exams.subject; deleting a teacher leaves them in subjects.teacher, classes.classTeacher and saved timetables; deleting a class strands students' studentClass. code-read
Impact
Relations are JSON columns with no foreign keys, so nothing catches it. Populated lookups quietly fall back to raw ids and the UI renders a hex string where a name should be.
G-13

Changing a user's email to one already taken returns a 500

~15 min
Evidence
Register checks for a duplicate; update does not. The unique index on lower(email) then throws, surfacing as a server error rather than a clear message. code-read
G-14

Seven menu items lead to “coming soon”

varies
Evidence
Assignments, Study Materials, Fee Collection, Expenses, Salary, School Settings, Roles & Permissions. All are advertised in the sidebar with no page behind them. They now degrade gracefully rather than erroring, but they still promise features that do not exist.
Fix
Hide them until built — a menu is a promise.
G-15

Activities Log shows the dashboard

~2 hours
Evidence
/activities-log is wired to the Dashboard component in the router. code-read
Impact
Every write is already logged and the API paginates it — only the screen is missing. The audit trail exists and nobody can read it.
G-16

Logging out does not invalidate the token

~3 hours
Evidence
Logout clears the cookie. The JWT itself stays valid for its full 30 days; there is no revocation list. code-read
Impact
A copied token keeps working after sign-out, and deactivating a user does not end their current session. Acceptable for many apps — worth knowing you have accepted it.
G-17

The exam list is unpaginated

~30 min
Evidence
GET /api/exams has no LIMIT, unlike every other list endpoint. It returns every exam a teacher has ever created, questions included.
G-18

The footer is 16 placeholder links and a dead button

~1 hour
Evidence
16 anchors still point at href="#", including Privacy Policy and Terms of Service. The newsletter Join button has no handler and there is no subscriber storage. tested live
Impact
Privacy Policy and Terms are the two a real institution cannot leave dangling.
G-19

No self-service account creation of any kind

—
Evidence
No sign-up route, and no invite flow. Every account is typed in by an admin, and the very first admin must be seeded from the command line because registration itself requires an admin.
Impact
Deliberate for an LMS, but it means onboarding does not scale past a handful of people. G-05 is the first step toward fixing it.
G-20

Teacher dashboard “next class” is hardcoded

~2 hours
Evidence
The API returns the literal "Mathematics - Grade 10" at "10:00 AM" for every teacher. code-read
Impact
Timetable data exists to compute this properly; nobody wired it.
G-21

Accepted applicants have no class

~1 hour
Evidence
An application records a programme (“Data Architecture”), but classes are named things like “Grade 10”. Nothing maps one to the other.
Impact
Even once acceptance creates an account, that student sees no exams until an admin assigns a class by hand — because exam visibility is scoped entirely by class.
G-22

The public landing page calls authenticated endpoints

~15 min
Evidence
AuthProvider requests /users/profile and /academic-years/current on every page load, including for signed-out visitors, producing about a dozen 401s in the console on the landing page. tested live
Impact
Harmless — the errors are caught — but it is noise that hides real errors and wastes requests on the busiest page.
How this list was built. By auditing categories rather than clicking around: every navigation target against every defined route, every button for a handler, every delete for cascade behaviour, every role gate in the sidebar against the API, and every dashboard number against a real query. Findings marked tested live were reproduced against the deployed app; the rest are read directly from the source. Earlier passes that only spot-checked missed five dead buttons and a whole role's experience — hence the change in method.

Audited against the deployed build at eugene-lms.workplacefiles.com. G-05 and G-06 are being implemented now with Resend; the rest are open.
