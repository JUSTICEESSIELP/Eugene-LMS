Before any of it works

Four routes have to be visited in order on a fresh database. Nothing enforces this, and skipping a step makes the AI features fail rather than warn.

Academic YearsMark one current
→
SubjectsName + code
→
TeachersSet their Subjects
→
ClassesYear + teacher + subjects
→
StudentsAssign to a class
The trap. A teacher and a subject are linked in two independent places, and only one counts. Timetable generation reads the teacher's Subjects field, set on /users/teachers — not the Teacher field on the subject form. Miss it and generation fails with “No Teachers assigned to these class subjects”.

Public routes

Reachable with no account. Everything else redirects to sign-in.

/“Is this university for me?”

The marketing landing page. Its entire job is to move a stranger to /apply.

Who
Anyone
How you get here
Direct link · the Veya logo from /login or /apply · Back to homepage on a 404
What you do
Read programmes and stats; jump to apply or sign in.
/apply“I want to study here.”

Admissions enquiry form. The only route in the whole app that writes data without a session.

Who
Anyone — no account needed
How you get here
  • Apply Now in the navbar
  • Start application in the hero
  • Apply Now in the closing section
What you do
Name, email, programme (phone and note optional) → Submit application. It lands in the admin queue as pending.
Not a sign-up. This creates an application record, not an account — no password, no login. Accepting one later does not create a user either; an admin still adds them by hand.
/login“Let me into my account.”

The single entrance to everything private. Sets a 30-day httpOnly JWT cookie.

Who
AdminTeacherStudentParent
How you get here
Sign In in the navbar · the “Sign in” link under the apply form · automatic redirect from any private route when signed out · after logging out
What you do
Email and password → Sign In, then you land on /dashboard.
There is no sign-up route. Accounts are created only by an admin. The very first admin has to be seeded from the command line, because registration itself requires an admin.

/settings/academic-years“Open the 2026–27 school year.”

Step one on a fresh install. Everything else hangs off the year marked current.

Who
Admin
How you get here
System › Academic Years · Academic Settings in Quick Links · forced redirect when no current year exists
What you do
Add New Year → name, start and end dates, mark it current.
This route is a gate. With no current year, an admin is bounced here from every other page, and non-admins are bounced to sign-in. It is the first thing to fix on an empty database.

/timetable“When is my class?” / “Schedule the week.”

One route, two jobs: admins generate the schedule with AI, everyone else reads it.

Who
AdminTeacherStudentParent
How you get here
Academics › Timetable · View Timetable in Quick Links
What you do

/lms/exams“Set a quiz” / “What do I have to take?”

The assessment list, filtered server-side by who is asking.

Who
AdminTeacherStudent
How you get here
Learning (LMS) › Exams · Quizzes & Exams in Quick Links · Create Quiz on the teacher dashboard
What you do
  • Teacher / admin — New AI Quiz: subject, class, topic, difficulty, count
  • Student — see only published exams for their own class
Teachers see only their own exams. That filter is applied in the API, not just hidden in the UI. Generation takes about 5–6 seconds and produces an unpublished exam.
/lms/exams/:id“Take this quiz” / “Publish it.”

The one screen where the exam is actually worked on — and the role split is sharpest.

Who
AdminTeacherStudent
How you get here
Manage Questions (teacher/admin) or Start Quiz (student) on a card in /lms/exams
What you do
  • Teacher — review the AI's questions, then Publish Exam, Unpublish Exam or Delete Exam
  • Student — answer, Submit Exam, then see Review Answers with the marking
Generating is not publishing. New exams are inactive on purpose so a human checks the model's work. Until someone publishes, no student sees it — which reads like the AI silently failed. Students get one attempt, and correct answers are stripped from their payload until they submit.
/admissions“Who applied this week?”

The menu hides links; it does not lock routes. Nothing in the router checks a role, so any signed-in user — a parent, the lowest-privilege role — can type /admissions, /classes or /users/admins and get the full admin screen, buttons and forms included. Verified by signing in as a parent and visiting each one. No data leaks: every table comes back empty because the API returns 403, which is the boundary that actually matters. But the UI should not be offering controls that cannot work. The fix is a role check on the private routes, roughly the same shape as the sidebar filter that already exists.
