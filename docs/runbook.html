Start here: the setup chain

These steps depend on each other and nothing in the UI enforces the order. Run them left to right on a fresh database, or the AI features will fail with a real error.

Students Assigned to a class
The one that catches everyone. A subject and a teacher are linked in two independent places, and only one of them counts for timetables. Setting Teacher on the subject form is not enough — timetable generation reads the teacher's own Subjects field, so you must also edit the teacher under People › Teachers and set it there. Miss this and generation fails with “No Teachers assigned to these class subjects”.

Goal: stand up a school from an empty database

The full setup chain, roughly ten minutes.

  1. System › Academic Years → Add New Year. Fill Year Name, Start Date, End Date, tick current. Nothing else can be created until a current year exists.
  2. Academics › Subjects → Create Subject. Give it a Name and a unique Code.
  3. People › Teachers → Add Teacher. Set Full Name, Email Address, Password, and Subjects. The Subjects field here is the one timetable generation reads.
  4. Academics › Classes → Create Class. Set Name, Year, class teacher, Subjects, Max Capacity. A class with no subjects attached cannot produce a timetable.
  5. People › Students → Add Student, setting Class. Students only ever see exams for the class assigned here.

Goal: generate a weekly timetable

Gemini schedules the week, avoiding teacher clashes across classes.

  1. Academics › Timetable
  2. Pick Academic Year and Class, then set Start Time, End Time, Periods / Day.
  3. Click Generate with AI. The button becomes “Optimizing Schedule…”.
  4. Wait. The grid fills in on its own. Takes about 10–12 seconds. The page refetches after 5, so it is normal to see “no schedule” once before it appears — reselect the class to refresh.
If it never appears, the class is missing subjects, or no teacher has those subjects on their own record. See the setup-chain warning above.

Goal: review an admissions application

Applications arrive from the public /apply page with no account attached.

  1. Admissions › Applications
  2. Filter by status, or search by applicant name or email.
  3. Use the row's status dropdown to move it: pending → reviewing → accepted or rejected.
  4. To enrol an accepted applicant, create them separately under People › Students. Accepting does not create an account — the two are not yet wired together.

Goal: create an AI quiz and publish it to a class

Two distinct actions — generating does not publish.

  1. Learning (LMS) › Exams, or Create Quiz on the dashboard.
  2. Click New AI Quiz.
  3. Fill the dialog: Subject, Class, Topic / Concept, difficulty, and question count (1–20).
  4. Submit. You get “AI is generating the exam!” straight away. The response returns immediately; Gemini writes the questions in the background, usually within 5–6 seconds.
  5. Reload the list, then click Manage Questions on the new card to check what it wrote.
  6. Click Publish Exam. Generated exams are created inactive on purpose. Until you publish, no student can see it.
Review before publishing. The questions are model output. You can also Unpublish Exam or Delete Exam from the same screen.

Goal: see how students did

  1. Learning (LMS) › Exams → Manage Questions on the exam.
  2. Correct answers are visible to you here, and stripped from what students receive.
Gap worth knowing. There is no per-class results table in the UI. The dashboard shows a “pending grading” count, and the API can return any student's submission, but no screen lists them yet.

Goal: take a quiz and see the result

Grading is instant — the score comes back in the submit response.

  1. Sign in at /login. You land on the dashboard.
  2. Learning (LMS) › Exams, or Quizzes & Exams under Quick Links.
  3. Click Start Quiz on a card. An empty list means nothing is published for your class yet, not that something is broken.
  4. Answer each question, then click Submit Exam.
  5. The view switches to Review Answers, marking your choices against the correct ones. Correct answers are withheld by the server until you have submitted.
One attempt only. A second submission is refused with “Exam already submitted”. There is no timer enforcement — the duration is displayed but not policed.

Goal: check the week's timetable

  1. Academics › Timetable, or View Timetable under Quick Links.
  2. The grid shows subjects, teachers, and times. Generation controls are hidden for students.

Parent

Defined everywhere but built nowhere. An admin can create parent accounts and they can sign in — but there is no parent experience behind the login.

Lands on
An empty student-shaped dashboard
Sees in menu
Dashboard, and an Academics group whose only visible item is broken
Cannot
View exams, classes, or subjects — all return 403

What actually happens

Traced through both the UI and the API.

  1. They sign in successfully — the role is valid in the database.
  2. The dashboard falls through to the student cards, and the API returns no stats for parents, so it renders 0%, 0, None.
  3. The menu shows Academics, but Classes, Subjects, and Timetable are all gated to other roles. The single item left is Attendance, which has no page behind it.
Recommendation: hide the role until it works. Removing parent from the user-creation dropdown takes minutes and stops anyone being handed an account that leads nowhere. Building it properly needs a parent→child link on the user record, which does not exist yet, and Attendance has no data model at all — the attendance percentages elsewhere in the app are hardcoded placeholders.

Visitor

Anyone with the link and no account. The only unauthenticated write path in the whole API.

Goal: apply without an account

  1. On the landing page, click Apply Now or Start Application. Both go to /apply.
  2. Fill Full name, Email, and Programme. Phone and the note are optional.
  3. Click Submit application. A confirmation screen replaces the form.
  4. It lands in the admin queue as pending. Applying twice for the same programme with the same email is refused while the first is still pending.

Goal: get into the app

  1. Click Sign In in the navbar, or go to /login.
  2. Enter Email Address and Password, click Sign In.
There is no self-registration. Accounts are created by an admin. The first admin on a fresh database has to be seeded from the command line — registration is admin-only, so nobody exists who could authorise the first one.
